## Confirmed functional gaps

### UI-01 — Saved actual harvest mass is absent from history/detail (REQ-008, AC-084/AC-085)

- Obligation: a recorded optional actual mass must be readable on SCREEN-005, including after restart; SCREEN-005 explicitly requires a metric unit.
- Production anchors: `shared/data/src/commonMain/kotlin/com/sedsoftware/sproutpace/data/ProductionScreenSnapshotRenderer.kt:119` builds the terminal outcome item with only occurrence time and reason/note; `shared/component/src/commonMain/kotlin/com/sedsoftware/sproutpace/component/BatchHistoryProjection.kt:6` has no mass field. `shared/data/src/commonMain/kotlin/com/sedsoftware/sproutpace/data/ProductionScreenInteractionBuilder.kt:526` supplies only batch state/substrate/tray/seed-mass/recipe/observation facts. `shared/compose/src/commonMain/kotlin/com/sedsoftware/sproutpace/compose/BatchDetailScreen.kt:182` renders history without actual harvest mass. `ProjectionContent.kt:12` also has no actual-mass presentation.
- Reproduction/consequence: close an active batch as harvested with 42.5 g, return to Batch detail/History, restart, and reopen. The result, date and note can be read, but 42.5 g is not shown. More actions exposes an editor, which is not the required history presentation. Seed mass is a separate fact and cannot substitute.
- Existing assertion limit: `ProductionScreenDataManagerIntegrationTest.kt:660` sends an actual mass to the manager. `BatchDetailProjectionTest.kt:26` checks dated outcomes/repeat/action filtering, not rendered mass. `ContextualFormsTest.closeBatchExposesOnlyOutcomeRelevantFields` proves the input exists, not that the saved value is readable. Committed harvested detail golden `[122]` was visually inspected and shows no mass in its visible header; source tracing establishes the full missing path.

### UI-02 — Missing harvest mass is prefilled with seed mass (REQ-008, AC-085; SCREEN-010 actual-only mass rule)

- Production anchor: `shared/data/src/commonMain/kotlin/com/sedsoftware/sproutpace/data/ProductionScreenInteractionBuilder.kt:322` uses `(harvested.actualMass ?: batch.actualSeedMass)` for `actualMassGrams`. `shared/compose/src/commonMain/kotlin/com/sedsoftware/sproutpace/compose/BatchDetailScreen.kt:177` exposes that field for `record-actual-mass`; line 147 submits it directly.
- Reproduction/consequence: harvest a batch without entering an actual mass. On terminal detail choose More actions → Record actual mass. The field contains the seed mass even though no harvest measurement exists. Save without changing it and the app records seed weight as actual harvested weight. A nullable optional measurement must remain blank until the user supplies it.
- Existing assertion limit: `BatchActionFieldsTest.kt:10` checks which transition fields are exposed; it has no missing-mass/default-value assertion. The terminal action-set assertion at `ProductionScreenDataManagerIntegrationTest.kt:754` checks availability of record mass, not that its value remains absent. No assertion inspected covers this fallback.

### UI-03 — Non-stage task Complete/Skip commands are unreachable on Batch detail (REQ-006, AC-061/AC-063 SCREEN-005 branch)

- Production anchors: `shared/data/src/commonMain/kotlin/com/sedsoftware/sproutpace/data/ProductionScreenSnapshotRenderer.kt:440` attaches `complete-action`/`skip-action` item commands to a pending non-stage task. `shared/compose/src/commonMain/kotlin/com/sedsoftware/sproutpace/compose/BatchDetailScreen.kt:88` renders scheduled tasks with `BatchHistoryCard`; that composable at line 182 renders projections but never item commands or action callbacks. `shared/data/src/commonMain/kotlin/com/sedsoftware/sproutpace/data/ProductionActionProjection.kt:45` builds the screen-wide permitted action set without either task command.

The corresponding Today commands exist; requiring a detour to Today does not satisfy the explicitly required SCREEN-005 operation surface.
- Existing assertion limit: `ProductionScreenDataManagerIntegrationTest.ac061Ac063_nonStageCompletionAndSkipKeepLaterBatchWork` at line 588 invokes `execute(ScreenId.TODAY, ...)` at lines 618/633. ### UI-04 — Advertising decision omits its explanatory copy (REQ-010, AC-102; SCREEN-015)

- Obligation: clear Accept/Decline/Policy actions with neutral explanation, including what the choice covers and its distinction from OS privacy controls.
- Production anchors: `shared/compose/src/commonMain/kotlin/com/sedsoftware/sproutpace/compose/ScreenContent.kt:1755` renders privacy via generic `ModelSinglePane`: hero, items, policy-version facts, actions. `screenHero` at line 1898 has no advertising-privacy branch. `RootUiAdapter.kt:379` decorates the privacy state with choice/applicability/policy and actions, without explanatory content. Production string resources exist (`values/strings.xml:21`: `privacy_decision_body`, `privacy_stale_body`, `privacy_context_title`, `privacy_context_body`) but none is referenced by production Kotlin.
- Reproduction/consequence: reach the first eligible protected-region moment. The screen says Your advertising choice / Not decided and current policy version, then Accept, Decline and Open privacy policy. It never explains what accept or decline does, that core features remain available, or the scope relative to OS controls. The committed `[50]` light Privacy golden was inspected and confirms this omission. Equal prominence of Accept and Decline is correctly implemented.
- Existing assertion limit: `RootUiAdapterTest.privacyDecisionActionsAreEqualAndAcceptedStateOffersWithdrawal` checks action list/prominence and accepted withdrawal, not explanation presence. Resource completeness does not prove a resource is presented.
