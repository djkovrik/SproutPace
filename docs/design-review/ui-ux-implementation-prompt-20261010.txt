Общие макеты
- Today: title/settings → один next action (глагол + различимая партия + срок) → просрочено → сегодня → предстоящий посев/урожай и capacity. Hero action не дублировать в списке.
- Batch detail: имя/культура/лоток/текущий этап → следующий шаг + CTA → дата/место/конфликт → компактная timeline → observations → immutable snapshot/history. Редкие действия в overflow, с названиями и правильной доступностью по lifecycle.
- Plan: режим/частота/rotation → датированная очередь подтверждённых и предлагаемых посевов/урожаев → контекстная вместимость. Suggestion содержит объяснение и Accept; Accept открывает editor, Save создаёт batch. Конфликт имеет предмет и actionable решения.
- Built-in recipe: название + cover + краткие реальные ranges → Use recipe → инструкции → safety/source/version/review. Отдельный personal editor. Primary CTA не за длинной лентой.
- Forms: контекст → относящиеся к задаче поля → optional секции → одна понятная Save, Cancel/Back. Sticky bottom сохраняет доступ с IME и 200% без перекрытия последнего поля. Delete отдельно, только существующая сущность.
- Compact <600: одна панель, навигация с иконками и видимыми подписями; medium 600–839: rail и ограниченная колонка; expanded >=840: настоящая list-detail для нужных сущностей; >=1200 expanded rail согласно spec. Не растягивать короткие формы на весь экран.
- 16dp компактный outer margin; общие semantic spacing/type/shape/color роли. One safe-area owner, никаких двойных inset. 48dp targets, heading/order, state + non-color cues, видимый focus. Не добавлять декоративное движение; reduced motion сохранять.

Проблемы и критерии приёмки

UX-01 [P1] Категории лотков не совпадают с production-статусами
Экраны: 003; связь со spec: AC-031, AC-083, AC-100.
Доказательство: ProductionScreenSnapshotRenderer.batchStateKey возвращает trays_planned и outcome_harvested/failed/abandoned. RootUiAdapter.visibleItems ожидает option_batch_state_planned и option_batch_state_*. Поэтому planned/terminal попадают в Active, а Planned/History не получают свои записи. Это подтверждённое несовпадение кода; runtime-прогон не выполнялся.
Якоря: shared/data/src/commonMain/kotlin/com/sedsoftware/sproutpace/data/ProductionScreenSnapshotRenderer.kt:406; shared/compose/src/commonMain/kotlin/com/sedsoftware/sproutpace/compose/RootUiAdapter.kt:413; shared/compose/src/commonMain/kotlin/com/sedsoftware/sproutpace/compose/RootUiAdapter.kt:516.
Исправление: Передавать типизированную категорию/состояние партии независимо от перевода. Фильтровать по ней, определять empty после фильтра. Не чинить только preview-ключи. В History показывать исход, дату, название партии; добавить контекстные Edit/Repeat/Delete по допустимому состоянию.
Проверка результата: В одной production fixture иметь planned, soaking, light growth, harvested, failed, abandoned. Каждая запись ровно в своей категории; выбор сохраняется при обновлении; empty соответствует выбранной вкладке. История доступна после закрытия партии.
